# Accessibility Audit

**Audited:** 2026-08-17 · CogniDiff v1.0
**Scope:** landing page, dashboard, mini-tasks, doctor report, sign-in.
**Method:** scripted audit in-browser — WCAG 2.1 contrast maths with correct
alpha compositing, plus keyboard and screen-reader checks by hand.

This is a health tool. Colour alone is not an acceptable signal, and a chart
that only exists as pixels is a chart that does not exist for some of the people
who need it most.

## What the first audit found

The initial pass found **37 contrast failures on the dashboard alone**, at
ratios as low as **3.11:1** against a required 4.5:1.

The cause was the design system itself. The sci-fi HUD aesthetic leans on dim
blue-grey labels, and two palette tokens — `--faint: #566d92` and
`--muted: #7f95b8` — were chosen because they *looked* right against the deep
navy. They were used for metric names, table headers, card titles and the
telemetry rows: not decoration, but the labels telling you what every number on
the page means.

They failed at 3.11:1. That is comfortably illegible for anyone with reduced
contrast sensitivity — which, in a tool aimed partly at older users worried
about their cognition, is precisely the group you cannot afford to lose.

### Fixes applied

| Token | Before | After | Ratio on panel |
|---|---|---|---|
| `--faint` | `#566d92` | `#7589ad` | 3.11 → **5.2:1** |
| `--muted` | `#7f95b8` | `#93a9c8` | 4.4 → **7.5:1** |
| `--text-dim` | `#9db4d6` | `#aabfda` | 6.9 → **9.2:1** |

Every label below 10px was also lifted to a 10.5px floor. Sub-10px type had
been treated as visual texture, but each of those elements was carrying an
actual metric name.

Navigation links were additionally moved from `--muted` to `--text-dim` and from
10px to 11px — they measured 4.29:1, just under the line. Navigation is primary
content, not chrome.

**The aesthetic survived the fix.** The palette is still a dim blue-grey HUD; it
is simply a legible one. The reference look was never the reason it failed —
carelessness about which tone got used for real text was.

## Colour is never the only channel

Every alert state carries **colour + text label + icon glyph**:

| State | Colour | Label | Icon |
|---|---|---|---|
| STABLE | green | "Stable" | ✓ |
| MONITOR | yellow | "Monitoring" | ◉ |
| SIGNIFICANT_DEVIATION | orange | "Notable deviation" | ! |
| PERSISTENT_DEVIATION | red | "Persistent deviation" | ⚑ |
| RECALIBRATING | blue | "Recalibrating" | ↻ |
| INSUFFICIENT_DATA | grey | "Not enough data" | ◔ |

A red score ring means nothing to a red-green colourblind user and nothing at
all to a screen reader, so the state is always also written out. Enforced by
`test_every_state_carries_a_label_and_an_icon`.

The CogniScore ring changes colour by band **and** shows the number, and the
confidence badge spells out `CONFIDENCE 87% (HIGH)` rather than relying on hue.

## Charts have text equivalents

A `<canvas>` is completely opaque to assistive technology. Every chart is paired
with a generated prose summary:

> *"7-day CogniScore over 7 days: 6 readings, average 75, ranging 38 to 93,
> falling by 23 points from 61 to 38. Days without a reading are shown as gaps."*

On the dashboard these live in `.sr-only` elements. On the doctor report the
summary is **visible to everyone**, because it also has to survive being printed
in black and white.

Generated by `CogniCharts.describeTrend()`, so it can never drift out of sync
with the data the chart is drawing.

## Keyboard navigation

Walked with Tab and Enter only, no mouse:

| Check | Result |
|---|---|
| Every interactive element reachable | ✓ 28 tabbable elements on the dashboard, all reachable |
| Visible focus ring | ✓ 2px cyan outline, 3px offset, on every focusable |
| Skip link | ✓ first tab stop on every page, jumps to `<main>` |
| Logical tab order | ✓ follows visual order; no positive `tabindex` anywhere |
| Focus never trapped | ✓ |
| All actions operable by keyboard | ✓ including the toggle switch, radio scales, revoke buttons and all four mini-tasks |
| No unlabelled controls | ✓ **0** across all pages |

The mini-tasks were the one genuine risk — a reaction-time target and a pattern
grid are naturally mouse-shaped. Both are real `<button>` elements with
`aria-label`s, so they are clickable with Enter or Space.

## Motion

`prefers-reduced-motion: reduce` is honoured everywhere:

- All CSS transitions and animations reduced to 0.001ms.
- Starfield renders one static frame instead of animating.
- The particle brain stops auto-rotating and mouse parallax is disabled; scroll
  states snap instead of tweening.
- The CogniScore ring jumps to its value instead of counting up.

A drifting starfield behind a page about cognitive decline is exactly the kind
of motion that triggers vestibular symptoms, so this is not optional polish.

---

## Responsive

Checked at 375px (iPhone SE), 768px and 1280px.

- No horizontal body scroll at any width.
- Wide content — trend tables, the exclusion-reason breakdown — scrolls inside
  its own `overflow-x: auto` container rather than pushing the page sideways.
- The landing page's alternating left/right copy collapses to a single left-
  aligned column below 640px.
- Score ring and side statistics stack below 760px.
- Touch targets meet 44px on the primary actions.

---

## Print

The doctor report is designed to be printed or saved as PDF:

- Colours invert to black-on-white; the background field, starfield and brain
  canvas are hidden.
- Navigation and buttons are `display: none`.
- Cards get real borders and `break-inside: avoid`.
- The disclaimer prints with a heavy border and never splits across pages.
- The 90-day chart summary prints as text, so the report is still readable if
  the canvas does not render.

## Known gaps

1. **Not tested with a real screen reader.** The semantics are correct by
   inspection, but NVDA and VoiceOver would likely surface ordering and
   announcement issues that static analysis cannot. This is the most valuable
   next step.
2. **The mini-tasks are inherently visual.** Pattern memory and reaction time
   have no meaningful non-visual equivalent. They are optional, and the passive
   keystroke monitoring — the core of the system — requires no visual
   interaction at all.
3. **Contrast measured programmatically**, not against a physical display.
   Real-world legibility on a dim laptop screen in daylight is a different
   question.
4. **No cognitive-accessibility review.** For a tool whose users may be worried
   about their own cognition, plain-language review is worth doing properly, and
   has not been.
